# 问答质量评测

改检索方式、提示词或换模型之后，怎么知道回答是变好了还是变差了？跑一遍这套评测。

## 怎么跑

先启动服务（`npm run dev` 或 `npm start`），`.env` 里要有 `ADMIN_PASSWORD`，然后：

```bash
npm run eval:qa
```

脚本会临时建一个知识库，把 `eval/docs` 里的示例制度传进去，逐题提问并打分，跑完自动删除知识库，不会碰你的真实数据。
一次约 27 次模型调用。提问限速是每分钟 20 次，超过时脚本会自动等待。

结果存在 `eval/results/`（不会提交到仓库）。

## 常用参数

| 参数 | 作用 |
|---|---|
| `--baseline eval/results/某次.json` | 和那一次对比，列出"修好"和"退步"的题；有退步时退出码为 1 |
| `--min 90` | 通过率低于 90% 时退出码为 1 |
| `--only 题目编号` | 只跑这一题，可重复写多个，调试时用 |
| `--keep` | 跑完保留临时知识库，方便去网页上看回答 |
| `--docs 目录` `--cases 文件` | 换成你自己的文档和题目 |

## 怎么打分

每道题有两种：

- **有答案的题（`answer`）**：`expect` 是要点，里面每一组是"或"（任一说法出现即可），组与组之间是"且"（每组都要有）；
  `reject` 里的说法不能出现（用来抓答成过期数据的情况）；`sources` 里的文档都要被标注为来源。
- **该拒答的题（`refuse`）**：知识库里没有答案，回答必须说"未找到相关内容"。编一个答案就算错。这类题最能看出模型会不会瞎编。

比对时忽略空格和 Markdown 加粗，"5 天""**5** 天""5天"算同一个说法。

## 换成你自己的文档

最有价值的评测是用你自己的真实文档和真实问题（比如「待补知识」里被问得最多的那些）。

1. 把文档放进一个目录（目前只读 `.md`），例如 `my-eval/docs/`。
2. 写题目文件 `my-eval/cases.json`，格式和 `eval/cases.json` 一样：

```json
{
  "kbName": "我的评测库",
  "cases": [
    { "id": "annual-leave", "kind": "answer", "question": "年假怎么算？",
      "expect": [["5 天", "五天"]], "sources": ["请假制度.md"] },
    { "id": "no-answer", "kind": "refuse", "question": "公司有班车吗？" }
  ]
}
```

3. `npm run eval:qa -- --docs my-eval/docs --cases my-eval/cases.json`

## 注意

- 大模型每次的回答有随机性，同一题偶尔一次对一次错是正常的。看整体通过率和"退步"列表，不要盯着单题。
- 示例文档里的公司和数字都是虚构的。
- 打分是关键词匹配，能抓住"数字答错、没标来源、编造答案"，但判断不了措辞好不好。
